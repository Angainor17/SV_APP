1. ЧТО ТАКОЕ CARGO И ПОЧЕМУ ОН
================================================================================
Cargo (автор Yaron Koren) — расширение MediaWiki, которое превращает поля
шаблонов в столбцы настоящих SQL-таблиц. Редактор заполняет обычный шаблон на
вики-странице, а Cargo кладёт это в таблицу, которую можно запрашивать
программно (фильтрация WHERE, сортировка ORDER BY, агрегаты COUNT).

Для квизов это решает три вещи из ТЗ, которые не решают JSON-страницы:
  - "Новые квизы за последние 14 дней"  -> WHERE по дате
  - "Темы динамические"                  -> отдельная таблица тем
  - "Количество квизов в теме"           -> COUNT(*) / GROUP BY

================================================================================
2. ТРЕБОВАНИЯ (проверить ДО установки)
================================================================================
  - MediaWiki >= 1.35 (рекомендуется актуальная LTS; Cargo требует свежие
    версии — сверяйтесь со страницей расширения на mediawiki.org).
  - PHP, совместимый с вашей версией MediaWiki.
  - Доступ к файловой системе сервера (положить файлы в extensions/).
  - Доступ на правку LocalSettings.php.

!!! ГЛАВНОЕ ТРЕБОВАНИЕ !!!
Пользователь БД, от имени которого MediaWiki ходит в базу, должен иметь
привилегии CREATE TABLE / ALTER / DROP / INDEX. Cargo создаёт настоящие
таблицы, поэтому без CREATE-привилегии работать не будет. На общем хостинге
это самая частая причина отказа. Проверяется автоматически скриптом update.php
(см. п. 3, шаг 4) и на Special:CargoTables.

================================================================================
3. УСТАНОВКА РАСШИРЕНИЯ
================================================================================
Шаг 1. Скачать Cargo и положить в каталог extensions/Cargo:

    cd /путь/к/mediawiki/extensions
    git clone https://gerrit.wikimedia.org/r/mediawiki/extensions/Cargo

    (либо скачать архив с mediawiki.org и распаковать так, чтобы получился
     каталог extensions/Cargo с файлом extension.json внутри)

Шаг 2. Подключить расширение. В конце LocalSettings.php добавить:

    wfLoadExtension( 'Cargo' );

Шаг 3. (опционально) Если хотите хранить данные Cargo в ОТДЕЛЬНОЙ базе —
    необязательно, по умолчанию используется основная БД MediaWiki. Отдельная
    БД нужна редко; для квизов не требуется.

Шаг 4. Запустить обновление схемы БД (создаст служебные таблицы
    cargo_tables и cargo_pages, проверит привилегии):

    php maintenance/update.php

    Если привилегий CREATE нет — скрипт выдаст ошибку. На этом шаге вы
    узнаете, жизнеспособен ли Cargo на данном сервере, до всякой настройки.

5. СОЗДАНИЕ ПРОСТРАНСТВА ИМЁН Quiz
================================================================================
Квизы логично держать в отдельном пространстве имён "Quiz:". ID кастомных
пространств начинаются с 3000 и должны быть чётными. В LocalSettings.php:

    $wgExtraNamespaces[3000] = "Quiz";
    $wgExtraNamespaces[3001] = "Quiz_talk";

    // Псевдоним-константа для читаемости конфигов
    define( "NS_QUIZ", 3000 );

6. СОЗДАНИЕ ШАБЛОНОВ С #cargo_declare И #cargo_store
================================================================================
Каждый Cargo-шаблон описывает схему таблицы (#cargo_declare) и сохраняет
значения полей (#cargo_store).

6.1. Шаблон "Template:QuizQuestion" (один вопрос)

Создать страницу Template:QuizQuestion со следующим содержимым:

    <noinclude>
    {{#cargo_declare:_table=QuizQuestion
    |quiz=String
    |question=Text
    |type=String
    |option1=String
    |option2=String
    |option3=String
    |option4=String
    |option5=String
    |option6=String
    |correct=String
    |explanation=Text
    }}
    </noinclude>
    <includeonly>{{#cargo_store:_table=QuizQuestion}}</includeonly>

Пояснения:
  - String — короткая строка (до ~300 симв.); Text — длинный текст без лимита.
  - question и explanation — Text (вопрос и пояснение бывают длинными).
  - correct — String: для single-вопроса хранит НОМЕР правильного варианта
    ("2"), для input-вопроса хранит сам текст ответа ("Киев").
  - type — "single" или "input".
  - option1..option6 — варианты; для input-вопроса пустые.

6.2. Шаблон "Template:Quiz" (квиз целиком)

    <noinclude>
    {{#cargo_declare:_table=Quiz
    |title=String
    |theme=String
    |description=Text
    |image=String
    |created=Date
    }}
    </noinclude>
    <includeonly>{{#cargo_store:_table=Quiz}}</includeonly>

6.3. Шаблон "Template:QuizTheme" (тема)

    <noinclude>
    {{#cargo_declare:_table=QuizTheme
    |name=String
    |color=String
    |icon=String
    }}
    </noinclude>
    <includeonly>{{#cargo_store:_table=QuizTheme}}</includeonly>

ВАЖНО:
  - Типы Cargo: String, Text, Integer, Float, Date, Datetime, Boolean,
    Coordinates, Wikitext, File, URL и др. Полный список — в документации
    Cargo на mediawiki.org.
  - Cargo автоматически добавляет служебные поля в каждую таблицу:
    _pageName (имя страницы), _pageID, _pageTitle, _pageNamespace, _ID и др.
    Именно _pageName удобно использовать как уникальный ID вопроса/квиза.

================================================================================
7. СОЗДАНИЕ SQL-ТАБЛИЦ
================================================================================
#cargo_declare лишь объявляет схему. Физическая таблица создаётся отдельно —
вручную или скриптом.

Способ A (через веб):
  1. Открыть Special:CargoTables.
  2. Найти в списке QuizQuestion / Quiz / QuizTheme.
  3. Нажать "Create" (создать) у каждой.

Способ B (через консоль):

    php extensions/Cargo/maintenance/recreateData.php --table=QuizQuestion
    php extensions/Cargo/maintenance/recreateData.php --table=Quiz
    php extensions/Cargo/maintenance/recreateData.php --table=QuizTheme

После этого таблицы физически существуют (в БД они будут называться
cargo__QuizQuestion, cargo__Quiz, cargo__QuizTheme — префикс cargo__).

================================================================================
8. НАПОЛНЕНИЕ ДАННЫМИ (СТРАНИЦЫ КВИЗОВ)
================================================================================
После создания таблиц редактор создаёт обычные страницы, заполняя шаблоны.
Страницы вопросов кладём в пространство Quiz: (или любое другое по выбору).

Пример страницы вопроса "Quiz:История_Q1":

    {{QuizQuestion
    |quiz=История
    |question=В каком году основан Санкт-Петербург?
    |type=single
    |option1=1703
    |option2=1712
    |option3=1721
    |option4=1612
    |correct=1
    |explanation=Город основан 27 мая 1703 года Петром I.
    }}

Пример страницы квиза "Quiz:История":

    {{Quiz
    |title=История России: основные даты
    |theme=История
    |description=Проверьте знание ключевых дат
    |created=2026-07-25
    }}

После сохранения страницы строка попадает в SQL-таблицу. Если страницу
сохранили ДО создания таблицы — данные не запишутся; тогда после создания
таблицы выполните "Recreate" на Special:CargoTables или null-edit страницы
(открыть и сохранить без изменений).

9. ЗАПРОСЫ ЧЕРЕЗ API (CARGOQUERY) — ПРИМЕРЫ
================================================================================
Базовый URL: https://svremya.su/api.php
Аутентификация: НЕ требуется. Запросы анонимные (если вики публично читается).

9.1. Все вопросы квиза "История":

    https://svremya.su/api.php?action=cargoquery
        &tables=QuizQuestion
        &fields=_pageName,question,type,option1,option2,option3,option4,option5,option6,correct,explanation
        &where=quiz="История"
        &limit=500
        &format=json

    (значение строки в where берётся в двойные кавычки; кириллицу и кавычки
     надо URL-энкодить)

9.2. Список тем:

    https://svremya.su/api.php?action=cargoquery
        &tables=QuizTheme
        &fields=_pageName,name,color,icon
        &limit=500
        &format=json

9.3. Новые квизы за последние 14 дней:

    https://svremya.su/api.php?action=cargoquery
        &tables=Quiz
        &fields=_pageName,title,theme,description,image,created
        &where=created >= "2026-09-27"
        &order_by=created DESC
        &limit=100
        &format=json

9.4. Квизы по теме (WHERE по theme):

    https://svremya.su/api.php?action=cargoquery
        &tables=Quiz
        &fields=_pageName,title,description,image,created
        &where=theme="История"
        &format=json

9.5. Количество квизов в каждой теме (агрегат, опционально):

    https://svremya.su/api.php?action=cargoquery
        &tables=Quiz
        &fields=theme,COUNT(*)=quizCount
        &group_by=theme
        &format=json

    Если точный синтаксис алиаса COUNT(*)=... на вашей версии Cargo ведёт себя
    иначе — сверьтесь с докой Cargo; как запасной вариант приложение может
    получить темы и квизы и посчитать количество на клиенте.

Пример JSON-ответа (сокращённо):

    {
      "cargoquery": [
        {
          "title": {
            "_pageName": "Quiz:История_Q1",
            "question": "В каком году основан Санкт-Петербург?",
            "type": "single",
            "option1": "1703",
            "option2": "1712",
            "option3": "1721",
            "option4": "1612",
            "correct": "1",
            "explanation": "Город основан 27 мая 1703 года Петром I."
          }
        }
      ]
    }

Поддерживаемые параметры cargoquery: tables, fields, where, join_on, group_by,
having, order_by, limit, offset, format.

11. СКРЫТИЕ СТРАНИЦ ОТ ПОЛЬЗОВАТЕЛЕЙ
================================================================================
Задача: страницы-исходники квизов (Quiz:...) не должны быть видны обычным
пользователям, НО данные должны читаться анонимно из приложения.

Ключевой факт: после записи данные лежат в SQL-таблицах. Запрос cargoquery
читает SQL-таблицу, а НЕ вики-страницы, поэтому видимость страниц на него не
влияет. Скрытие страниц и анонимный API — две независимые вещи.

--- Уровень 1: мягкое скрытие (без расширений, рекомендуется начать с этого) ---
Страницы не находятся обычным пользователем, но по прямой ссылке открываются.

    // Не включать Quiz в контентные пространства -> не попадает в "Случайную
    // статью" и не считается основным контентом.
    // (по умолчанию кастомный namespace и так НЕ в $wgContentNamespaces —
    //  ничего добавлять не нужно)

    // Исключить из поиска по умолчанию:
    $wgNamespacesToBeSearchedDefault[NS_QUIZ] = false;

    // Не ставить нигде ссылок на страницы Quiz:.
    // Не добавлять Quiz в навигацию, категории-указатели, sitemap.

Итог: пользователь, не знающий URL, страницы не найдёт; приложение читает
данные через cargoquery.

--- Уровень 2: полное скрытие (read-запрет, расширение Lockdown) ---
Если нужно, чтобы даже по прямой ссылке страница не открывалась.

  Шаг 1. Установить расширение Lockdown (автор Daniel Kinzler) в
    extensions/Lockdown и подключить:

        wfLoadExtension( 'Lockdown' );

  Шаг 2. Создать группу редакторов квизов (если ещё нет):

        $wgGroupPermissions['quizeditor']['read'] = true;
        $wgGroupPermissions['quizeditor']['edit'] = true;
        // и выдать эту группу редакторам через Special:UserRights

  Шаг 3. Запретить чтение пространства Quiz всем, кроме этой группы:

        $wgNamespacePermissionLockdown[NS_QUIZ]['read'] = ['quizeditor'];

  Шаг 4. Проверить: аноним открывает https://svremya.su/Quiz:История ->
    получает "нет доступа"; редактор с группой quizeditor -> видит.

ВАЖНО при использовании Lockdown:
  - Приложение обязано читать данные ТОЛЬКО через action=cargoquery.
    Запросы action=parse или action=query&prop=revisions по страницам Quiz:
    упрутся в read-ограничение и анонимному клиенту вернут ошибку.
  - cargoquery при этом продолжает работать анонимно, т.к. выполняет SELECT
    по SQL-таблице cargo__*, не проверяя read-права исходных страниц.
  - После настройки Lockdown обязательно прогоните один тестовый запрос из
    п. 13, чтобы убедиться, что на вашей версии Cargo это действительно так.

12. ПРАВА ДОСТУПА: АНОНИМ = ЧТЕНИЕ, АДМИН = РЕДАКТИРОВАНИЕ
================================================================================
Задача: анонимный пользователь может только читать (этого достаточно для
приложения), а редактировать квизы — только авторизованные (администраторы).

Это стандартная модель MediaWiki, включённая по умолчанию:

    Группа      Чтение   Редактирование   Примечание
    * (аноним)    да          нет         читает, править не может
    user          да          да          обычный зарегистрированный
    sysop         да          да + админ  delete, protect, block и др.

Чтобы зафиксировать модель явно, в LocalSettings.php:

    // Аноним: только чтение, без правок и создания страниц
    $wgGroupPermissions['*']['read']       = true;
    $wgGroupPermissions['*']['edit']       = false;
    $wgGroupPermissions['*']['createpage'] = false;
    $wgGroupPermissions['*']['createtalk'] = false;

    // Зарегистрированные: чтение + редактирование
    $wgGroupPermissions['user']['edit']       = true;
    $wgGroupPermissions['user']['createpage'] = true;

    // sysop — по умолчанию уже имеет полный набор прав, ничего не добавлять.

--- Только администраторы редактируют квизы ---
Если править Quiz: должны ТОЛЬКО администраторы (обычные зарегистрированные —
нет), ограничь правку пространства имён через $wgNamespaceProtection и
собственное право:

    $wgNamespaceProtection[NS_QUIZ] = ['quiz-edit'];
    $wgGroupPermissions['sysop']['quiz-edit'] = true;

Тогда: аноним и обычный user читают, но править Quiz: не могут (нет права
quiz-edit); sysop читает и правит.

--- Связь с Cargo и приложением ---
  - Приложение читает квизы через action=cargoquery — это read-операция,
    работает анонимно, без токена. Права на запись приложению не нужны.
  - Редакторы (админы) залогинены и создают/правят страницы квизов; Cargo при
    сохранении страницы пишет строки в SQL-таблицу.
  - Предложение вопроса от пользователя (по ТЗ) идёт через email/Tracer, а НЕ
    через редактирование вики — поэтому анониму и не нужна запись.

--- Важно: "только чтение" ≠ "скрыто" ---
  - "Только чтение" (этот раздел): аноним ВИДИТ страницы и данные, но не может
    их править.
  - "Скрыть страницы" (раздел 11): аноним их НЕ видит, но получает данные
    через API.

Рекомендуемое для приложения сочетание: аноним = чтение + мягкое скрытие из
раздела 11 (Уровень 1); админ = редактирование. Жёсткое скрытие (Lockdown,
Уровень 2) делает "аноним = только чтение" уже не буквальным (аноним теряет и
просмотр страниц), хотя cargoquery при этом всё равно отдаёт данные.

14. ДИАГНОСТИКА И ЧАСТЫЕ ОШИБКИ
================================================================================
  - "Cargo did not create any tables" / таблицы нет на Special:CargoTables:
      не запускали create/recreate после #cargo_declare (см. п. 7).
  - Данные не записываются при сохранении страницы:
      таблица ещё не создана, либо страницу сохранили до её создания.
      Решение: Recreate таблицы, затем null-edit страниц.
  - Ошибка привилегий на update.php или Special:CargoTables:
      у пользователя БД нет CREATE/ALTER. Нужно выдать привилегии или сменить
      хостинг/пользователя БД. Это блокер Cargo.
  - cargoquery возвращает пусто, хотя страницы есть:
      проверьте where (двойные кавычки, URL-энкодинг), проверьте имя таблицы
      (без префикса cargo__) и что данные реально в таблице
      (Special:CargoTables -> "View" таблицы).
  - Запрос к скрытым страницам через action=parse даёт "нет доступа":
      это ожидаемо при Lockdown; переключите приложение на cargoquery.
